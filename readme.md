# Rubik Calculator

一个跨平台的桌面网格链式计算器：用户在二维表格中逐行录入「数字1 运算符 数字2」表达式，系统自动计算并展示结果，支持按「分组」属性的行/列统计汇总。每一行的多个表达式组可链式串联（前一组结果作为后一组的数字1）。

**技术栈**：Tauri 2 · React 18 · TypeScript 5 · Vite 5 · Zustand · decimal.js

---

## 1. 产品定位与平台

- 支持 Windows / Linux / macOS，产出对应安装包（msi/exe、.deb/AppImage、dmg）。
- 桌面容器采用 Tauri 2（复用系统 WebView，安装包约 5MB、内存 40–80MB、秒级启动），Rust 仅作纯壳，不含业务逻辑。

## 2. 核心数据模型

- **表达式组（逻辑列）**：固定占 5 个物理列，依次为 `数字1` / `运算符` / `数字2` / `=` / `结果`。
  - `数字1`、`数字2`：可编辑数值输入（支持小数）。
  - `运算符`：四则运算 `+ - * /`，通过表头每组的 `OperatorButton` 选择（列级统一，作用于该组所有行）。
  - `=`：只读展示符号（使用 `OperatorIcon` 图标），计算为全量自动重算，无需手动触发。
  - `结果`：只读，由计算引擎派生。
- **分组属性列**：位于数字列之前，用于给每行打分类标签（如「分组1」「分组2」），可编辑列名、可增删列；仅作统计维度，不参与运算。
- **行**：由一组或多组表达式组成；网格中**所有行的组数统一**（增加列对所有行同时生效，保持矩形结构）。
- **默认布局**：打开时 **1 行 × 1 组**（即 5 个物理列 × 1 行）+ 无分组属性列。
- **最小边界**：至少 1 行、至少 1 组。增/删行、增/删列均不得低于此下限。

## 3. 计算与统计规则

- **运算**：加、减、乘、除及小数；内部使用 `decimal.js`（precision 30，四舍五入）保证精度，规避浮点误差（如 `0.1 + 0.2`）。结果以 Decimal 字符串保存，**不出现科学计数法**，且不会超过 30 位有效数字精度。
- **链式只读**：「增加列」时，新组的 `数字1` 自动绑定为前一组的 `结果`，该单元格**只读**；其值随前组结果联动变化，不允许手工编辑。链式绑定优先于任何历史手工输入。
- **下游跳过**：若某一组的结果为「空」或「错误」（如除零），则该组之后的**所有后续组全部跳过计算**，结果标记为「空」，不抛错、不显示中间噪声。
- **错误与非法输入**：
  - 单元格留空 → 视为「空」，该组结果跳过。
  - 输入非数字内容 → 视为「错误」，触发下游跳过。
- **结果列显隐**：
  - 仅存在默认「数字1」一组（无运算项）时，**不显示结果列**（该列数值直接作为分组统计维度）。
  - 一旦新增运算项（第 2 组起），结果列由各运算项组承担，每组均带结果列。
- **统计口径**：
  - 按「分组」属性列聚合；每个结果列单独成一张统计表（多结果 = 多张表），表格标题可编辑（默认「结果」，第 0 组为「数字1」）。
  - 空白与错误单元格**跳过统计，不计为 0**（防止错误静默污染合计）。
  - **行结果**：取该行**最后一组的结果**（链式最终值），不采用逐组求和以避免重复计入中间值。
  - **列合计**：对该列（同组）各行的结果相加；操作数（数字1/数字2）合计统计输入值本身，行间独立。
  - **总计**：行结果与列合计不再满足「行合计之和 === 列合计之和」的自检等式（链式下该等式不成立）。
- **数值展示**：结果默认按当前小数位显示；底层数据保留完整精度，不截断。

## 4. 键盘交互

- **运算符设置**：通过表头每组左侧的 `OperatorButton` 选择 `+ - * /`，作用范围为**该组所有行（列级统一）**，无逐单元格运算符输入。
- **导航**：`Enter` 在「数字2」单元格按 → 跳到下一行同组；在无运算项（仅数字1）时，「数字1」按 `Enter` → 跳到下一行裸项；`Tab` 向右、标准表单焦点流。
- 焦点定位通过 `data-r/data-g/data-f` 属性 + `querySelector` 实现。

## 5. 操作能力

- 增加行 / 删除行（下限 1 行）。
- 增加列（以「组」为单位，对所有行统一增加）/ 删除列（下限 1 组）。
- 增加分组属性列 / 删除分组属性列。
- 设置小数位数（输入框失焦时按小数位重写，按键时不重写）。
- 所有增删均实时触发全量重算与统计刷新。

## 6. 架构分层

```
┌─────────────────────────────────────────────┐
│  Tauri 2 Runtime (Rust 纯壳)                  │
│  - 创建窗口，加载前端静态资源                  │
│  - 不含业务逻辑                                │
└─────────────────────────────────────────────┘
                    │ file:// 加载
┌─────────────────────────────────────────────┐
│  UI 层 (React + CSS Grid)                     │
│  - App / CalculatorGrid / Toolbar             │
│  - 键盘交互、只读链式单元、统计展示            │
├─────────────────────────────────────────────┤
│  状态层 (Zustand store)                       │
│  - 仅存用户输入；派生计算在 compute 中完成      │
├─────────────────────────────────────────────┤
│  领域层 (core/)                               │
│  - types.ts：三态单元格模型                    │
│  - engine.ts：纯函数计算 + 下游跳过 + 统计      │
│  - decimal.js：精确四则运算                     │
└─────────────────────────────────────────────┘
```

**关键原则**：store 只存用户输入（第 0 组 param1、各组的 operator 与 param2），所有结果、链式回填、统计均为**派生计算**，每次输入全量重算。默认规模仅 1×1，扩到 100×20 也仅 2000 次运算，性能充足，且彻底杜绝增量更新的状态不一致。

### 6.1 领域模型

| 类型 | 说明 |
| --- | --- |
| `Cell` | 三态：`empty` / `error(message)` / `number(value)`（value 为 Decimal 字符串） |
| `Group` | 一个表达式组 `{ param1, operator, param2, isItem }`；`isItem=true` 为裸项（第 0 组，结果=param1），`false` 为运算项；引擎消费时 param1 已是最终值 |
| `GroupResult` | 单组计算结果 + `skipped` 标记 |
| `RowResult` | 一行所有组结果 + `rowResult`（最后一组有效值） |
| `ComputeOutput` | 全部行结果 + 每组列合计 |

### 6.2 计算与链式算法

1. **精度**：`decimal.js`（precision 30，四舍五入），规避 `0.1+0.2` 浮点误差。
2. **链式派生**（`derive.ts`）：第 g 组（g>0）的 `param1` 由第 g-1 组的结果值回填，只读。
3. **下游跳过**（`engine.ts`）：遍历一行，一旦出现 `empty` 或非数字 `error`，后续所有组标记 `skipped=true`、结果置为「空」，不抛错；若某组自身的操作数为空或非数字，则本组无有效结果并阻断下游。
4. **行结果**：取该行**最后一组有效结果**（链式最终值），不采用逐组求和以避免重复计入中间值。
5. **列合计**：按组 g 分别聚合——`数字1 合计`、`数字2 合计`（操作数，行间独立相加，空/非数字单元格跳过）、`结果合计`（同组结果相加，无效/跳过单元格跳过）。
6. **总计**：行结果与列合计不再满足自检验等式（链式下该等式不成立）。

### 6.3 状态层（Zustand）

- `rows: StoredRow[]`，`StoredGroup = { param1?, operator, param2, isItem }`（裸项 `isItem=true` 有 param1；运算项 `isItem=false` 无 param1，其 param1 由链式派生回填）。
- Actions：`setColumnOperator / setParam1 / setParam2 / setHeader / setAttributeHeader / addRow / removeRow / addGroup / removeGroup / addAttribute / removeAttribute / setDecimalPlaces`。
- `compute()`：调用 `deriveForCompute(rows)` → `computeGrid(...)`，返回 `ComputeOutput`。
- `App` 用 `useMemo(() => computeGrid(deriveForCompute(rows)), [rows])` 派生，避免重复计算。

### 6.4 UI 层

- **布局**：CSS Grid 动态拼接列模板；行号列 + 分组属性列（浅蓝底）+ 每组 5 列 + 行结果列。表头只保留可编辑列名输入框（无「分组1/分组2」文字行、无蓝色分割线）。
- **键盘交互**：
  - 运算符经表头每组 `OperatorButton` 设置（列级统一），无逐单元格键入。
  - `Enter`：在 `数字2` 跳到下一行同组；仅数字1 时跳到下一行裸项；`Tab` 向右。
  - 焦点定位通过 `data-r/data-g/data-f` 属性 + `querySelector` 实现。
- **只读链式单元**：第 g>0 组的 `数字1` 渲染为 `readOnly` 输入框（灰底），不接收焦点。
- **视觉区分**：结果格（绿色背景，多结果时颜色渐深）、错误（红底样式）、行结果（黄底）；输入框宽度按内容自动适配（`useAutoSize` + canvas 测量）。

## 8. 环境准备

需安装：

1. **Node.js 18+** 与 npm
2. **Rust 工具链**（仅构建期需要）：https://rustup.rs
3. **平台依赖**（Tauri 官方要求）：
   - Windows：Microsoft C++ Build Tools + WebView2（Win10/11 默认已带）
   - macOS：`xcode-select --install`
   - Linux：`webkit2gtk-4.1` 与构建工具（`.deb` 会声明依赖）

## 9. 开发与打包

```bash
npm install
npm test        # 运行计算引擎单元测试（Vitest）
npm run dev     # 启动前端开发服务器（浏览器预览）
npm run tauri:dev   # 启动 Tauri 窗口（含 Rust 壳，热重载）
```

首次运行 Tauri 前，请生成图标：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/gen-icons.ps1
```

> 该脚本在 Windows 上用 .NET 生成占位 PNG。macOS 打包还需 `icon.icns`，
> 可在 Mac 上用 `npx tauri icon <源图>` 正式生成。

打包：

```bash
npm run tauri:build
```

产物位于 `src-tauri/target/release/bundle/`：
- Windows：`*.msi` / `*.exe`
- macOS：`*.dmg`
- Linux：`*.deb` / `*.AppImage`

## 11. 已知取舍

- 三平台 WebView 内核不同，渲染非像素级一致——仅用标准 CSS Grid 与表单控件规避。
- 计算引擎置于前端，未用 Rust（场景计算量极小，IPC 收益不可感知）。
- 本期不实现：保存/读取文件、导出 CSV/Excel、深浅色主题。
